# Cognitive Bias Prediction Platform

IB Computer Science Extended Essay — research tool for
"To what extent can machine learning models predict the decisions of large language models on cognitive bias tasks?"

---

## Repository structure

```
cogbias/
  collect_llm_data.py        Drive LLMs through 30 scenarios; writes data/llm_responses.csv
  scenarios.py               30 scenario templates + per-responder parametric generator
  pipeline.py                Standalone ML pipeline (importable + runnable as a script)
  config.py                  Global constants, feature spec, encodings, RNG seed
  .env.example               Copy → .env and fill in API keys
  requirements.txt
  sample_data/
    make_synthetic.py        Generate synthetic data for pipeline testing
    synthetic_responses.csv  Auto-generated by make_synthetic.py
  deprecated/                Former Streamlit/Supabase human-survey components
```

## Quick start

### 1 — Add API keys

```bash
cp .env.example .env
```

Edit `.env` and set at minimum one of:
- `OPENAI_API_KEY` — gpt-4o, gpt-4o-mini
- `ANTHROPIC_API_KEY` — claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5
- `GOOGLE_API_KEY` — gemini-1.5-pro, gemini-1.5-flash
- `TOGETHER_API_KEY` — llama-3.1-70b, mistral-large, qwen-72b

### 2 — Install dependencies

```bash
pip install -r requirements.txt
```

### 3 — Collect LLM responses (~30 min, ~$3–8 in API credits)

```bash
python collect_llm_data.py
```

Writes `data/llm_responses.csv` (~1,500 rows: 10 models × 5 temperatures × 30 trials).

To validate without API calls:

```bash
python collect_llm_data.py --dry-run
```

### 4 — Run the ML pipeline

```bash
python pipeline.py data/llm_responses.csv out/
```

Outputs printed metric tables and four figures in `out/`:
- `confusion_matrix_lr.png`
- `confusion_matrix_nn.png`
- `accuracy_by_bias_type.png`
- `lr_coefficients.png`

### 5 — Test the pipeline before real data (optional)

```bash
python pipeline.py sample_data/synthetic_responses.csv sample_data/
```

## Design

Each `(model, temperature)` pair is treated as a single "responder" with a UUID.
`GroupKFold` groups by `participant_id` (aliased from `responder_id`) so no responder
appears in both train and test within a fold.

Across the 50 responders (10 models × 5 temperatures), the ML models learn whether
scenario features (frame, anchor_value, expected_value_ratio, bias_type) predict
the LLM's choice — the same way they would predict a human's choice.

---

## Reproducibility

- `config.py:GLOBAL_SEED = 42` seeds Python `random` and NumPy.
- Each responder's scenario set is deterministic from its `responder_seed`.
  Re-running `generate_participant_scenarios(seed)` with the same integer always
  yields the identical 30 scenarios in the same order.
- Pin package versions by using `requirements.txt` verbatim.

## Feature reference

| Feature               | Type  | Description |
|-----------------------|-------|-------------|
| `trial_index`         | int   | 1–30: position in this responder's randomised order |
| `bias_type`           | int   | 1=framing, 2=anchoring, 3=loss_aversion |
| `frame`               | int   | 0=gain frame, 1=loss frame |
| `expected_value_ratio`| float | EV(on-screen A) / EV(on-screen B) |
| `anchor_value`        | float | Anchor shown; 0 for non-anchoring trials |
| `previous_choice`     | int   | 0/1 — choice on immediately preceding trial |
| `is_first_trial`      | int   | 1 if trial 1 (previous_choice undefined), else 0 |
| `reaction_time_ms`    | int   | ms from prompt send to first token received |
| **`choice`**          | int   | **Target**: 0=A, 1=B |
